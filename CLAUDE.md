No test suite is configured.

## Architecture

**Seller dashboard** (Next.js 16 App Router) for managing products, orders, and store profile. The backend runs separately on port 5003.

### Routing

Two route groups in `src/app/`:
- `(auth)/` — unauthenticated pages: register (`/register`), create store (`/store`)
- `(site)/` — authenticated pages with shared `Layout` (Header + main): home, products, orders, profile

Each route page is a thin shell that imports from `src/pages/<feature>/`, which holds the actual component logic.

### API Layer

`src/api/generated/` is **auto-generated by Orval** — do not edit manually. Regenerate with `bun generate-api` when the backend OpenAPI spec changes.

- `src/api/index.ts` — Axios instance with `NEXT_PUBLIC_API` base URL and Bearer token injection from `localStorage`
- Generated hooks follow the pattern `useGetXxx` / `usePostXxx` / `usePatchXxx` / `useDeleteXxx`
- All API hooks are React Query wrappers generated per endpoint tag (auth, category, favorite, order, product, saller, search)

### State & Data Fetching

- React Query (`@tanstack/react-query`) for all server state — configured with `staleTime: 60s` in `src/provider/Provider.tsx`
- Zustand available for client-only state (imported but used per-feature)
- Auth token stored in `localStorage` (not httpOnly cookies — note the deviation from global CLAUDE.md)

### Styling

SCSS Modules (`.module.scss`) per component. Global styles in `src/app/globals.scss`. Tailwind CSS v4 is also available but SCSS Modules are the primary styling pattern in this codebase.

### Key Conventions

- `'use client'` only in leaf components or provider wrappers — layout and page files are Server Components
- `layout.c.tsx` naming suffix is used for the client-side layout wrapper (splits server/client boundary at root)
- `FormData` (not JSON) for product create/update — arrays sent as `field[]` keys (e.g., `sizes[]`, `colors[]`)
- `useGetCategories` returns a tree structure; category selection walks the tree level-by-level
